# 重命名包名的资源兼容设计

日期：2026-09-24

## 背景

独立封装模式保留原包名时，`wrapper-smoke` 的动态资源查询结果为
`namedResource=true`。将同一 APK 重命名为 `example.npatch.renamed` 后，应用其余
加载检查通过，但以下查询返回 `0`：

```java
getResources().getIdentifier("smoke", "layout", getPackageName())
```

当前外层 APK 原样复制 `resources.arsc`，运行时又从缓存中的原 APK 加载资源，
因此资源表包命名空间仍是原包名。应用使用新包名进行动态资源查询时必然失败。

## 目标

- 重命名封装后，使用新包名动态查询资源能够成功。
- 应用或第三方 SDK 中硬编码的原包名查询仍能成功。
- 资源 ID、资源内容和资源表块大小保持不变。
- `assets/base.apk` 保持逐字节不变。
- 保留包名的默认封装不改变现有资源加载行为。

## 非目标

- 不重写 DEX、SO 或脚本中硬编码的包名。
- 不为任意第三方包名建立资源别名。
- 不复制或修改内嵌原 APK 来生成第二个运行时 APK。
- 不支持 split APK、动态功能分包或共享资源库的包名迁移。

## 方案

采用“资源表重命名 + 原包名运行时兼容映射”。

### 打包期资源表处理

新增 `WrapperResources`，解析 `resources.arsc` 的顶层资源表和包块，仅修改与原包名
完全匹配的 `ResTable_package` 名称字段。该字段为固定长度 UTF-16LE 区域，因此重写
不得改变资源表长度、块偏移、package ID 或任何资源 ID。

处理规则：

1. 目标包名与原包名相同时，原样复制资源表。
2. APK 没有 `resources.arsc` 时允许继续生成。
3. 存在资源表但格式越界、包块损坏或找不到原包名时，重命名生成失败并报告明确错误。
4. 新包名无法放入固定名称字段时拒绝生成，不截断包名。
5. 只重写主应用包块，不修改框架、共享库或其他包块。

`WrapperPacker` 在包名改变时将 `resources.arsc` 加入重写项；其他资源和 assets 继续
保持原压缩方式。内嵌的 `assets/base.apk` 不参与重写。

### 运行时资源路径

重命名模式下采用分离路径：

- 应用代码、DEX 和原生库继续来自校验后的原 APK 缓存。
- `LoadedApk.mResDir` 和资源目录指向外层 APK，使 Android 加载已改为新包名的资源表。
- `ApplicationInfo.sourceDir` 继续表示原 APK 代码路径，不把外层加载器当作应用代码。

仅在 `originalPackage` 与 `newPackage` 不同时启用该资源路径；保留包名模式维持当前
代码与资源同源的行为。

### 原包名兼容映射

新增 `ResourcePackageCompat`，在原应用 `Application` 创建前安装一次资源查询兼容：

- `Resources.getIdentifier(name, type, originalPackage)` 改为查询 `newPackage`。
- 完整名称 `originalPackage:type/name` 改写为 `newPackage:type/name`。
- 已使用新包名的调用不修改。
- 查询其他应用包名时不修改。
- 映射只在重命名独立封装模式启用。

资源表以新包名作为唯一真实命名空间，运行时兼容层只为旧包名调用提供别名。这样
新包名符合安装身份，同时保留常见 Java 动态查询的旧包名兼容性。

## 错误处理

- 资源表重写失败时禁止输出 APK，避免生成能够安装但动态资源查询必然失败的产物。
- 运行时兼容 Hook 安装失败时记录明确错误；重命名模式将其视为启动失败，避免静默
  丢失旧包名兼容能力。
- 所有资源表解析均进行长度、块大小、头大小和 UTF-16 终止符校验。

## 测试

### 本地测试

- 合法资源表包名从原包名改为新包名。
- package ID、资源 ID、文件长度和非名称字节保持不变。
- 保留包名时资源表字节完全不变。
- 多包块时只修改匹配原包名的主包块。
- 截断、越界、非法块大小、缺少匹配包块和过长目标包名均被拒绝。
- 封装输出中的外层 `resources.arsc` 使用新包名，`assets/base.apk` 与输入 SHA-256
  一致。
- 资源查询映射覆盖分离参数形式和完整资源名称形式，并且不影响其他包。

### 真机验收

以 `wrapper-smoke-debug.apk` 为输入，重命名为 `example.npatch.renamed`：

- 应用冷启动完成且不崩溃。
- `getPackageName()` 返回新包名。
- 使用新包名查询 `layout/smoke` 成功。
- 使用原包名查询同一资源成功。
- 静态 `R.layout.smoke`、布局加载、自定义 View、组件、代码路径和原生库检查通过。
- 未重命名样例继续完整通过。

## 已知边界

Java 资源查询兼容不能保证覆盖应用在 JNI 中自行解析资源表、直接解析 APK 或校验
资源表字节的行为。此类应用仍可能拒绝重命名封装，应在生成或测试阶段明确报告，
不能把启动成功等同于业务兼容。

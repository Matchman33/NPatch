# 发布可靠性与大型 APK 任务设计

用户已授权实施，仅做本地验证，不连接真机。

## 范围

1. 工作空间持有会话文件锁，清理只回收无锁的会话；删除失败记录警告，禁止跨目录删除。
2. ZIP 溢写文件放在输出任务目录中，正常退出统一回收，异常退出由下一次会话清理接管。
3. 显式固定版本号；管理器正式 Release 必须配置签名，本地验证可显式选择测试签名并标识产物。
4. 修复管理器 API 28 兼容检查，让管理器 Release 构建执行 lint。
5. 专用 CI 构建管理器、CLI，执行测试、lint、签名验证和摘要生成。CI 不自动发布 Release。
6. 多个窗口共享进程内任务状态，长操作由前台服务维持，显示阶段/字节进度并支持协作取消。进程被杀后不自动重试输入流。
7. 打包前根据 ZIP 条目大小、运行时和中间文件估算空间，复制过程中检查剩余空间。
8. 运行时提取原包时同步计算摘要，消除提取后重复读取；缓存命中仍完整校验，不以时间戳代替完整性验证。原包代际锁保护活跃进程，回收未被使用的旧摘要文件。

## 本地验收

- 双活跃会话不互删、关闭会话可回收、目录边界与删除失败提示。
- 打包成功/失败/取消后的临时目录、输出文件和内嵌原包校验。
- 空间估算覆盖压缩原生库，取消复制不保留部分输入。
- 原包损坏修复、摘要错误不发布、活跃代际不回收、陈旧代际回收。
- 管理器与加载器 JVM 测试、管理器 lint、CLI 与管理器构建。
- 正式签名缺失的构建必须失败；本地验证包明确标识测试签名。
- 记录本地摘要 I/O 测量；不据此宣称真机启动性能或后台存活已经验证。

# 管理器工作空间清理设计

## 问题

管理器每次选择 APK 都会在私有目录创建新的 UUID 输入快照，每次生成也会创建新的 UUID 输出目录。界面状态失效时只清空内存中的 `output`，没有删除对应文件，因此大 APK 在重复选择、修改参数和重新生成后会持续累积。

单次打包仍需要合理的临时空间。若原 APK 大小为 `S`，输入快照约为 `S`，外层 APK 因包含原始内容和完整的 `assets/base.apk`，通常接近 `2S`，打包期间峰值可能接近 `3S`。本次修复消除跨操作累积，不承诺消除这部分必要峰值。

## 设计

- 临时输入、输出、Gadget 和脚本统一放入 `cacheDir/wrapper/session-<UUID>`。
- 每个进程会话只保留当前选择的 APK、当前选项文件和最新生成结果。
- 启动时删除其他缓存会话，并删除旧版本遗留的 `filesDir/wrapper`。
- 成功选择新 APK 后删除上一个选择目录；无效 APK 只删除本次暂存目录。
- 修改包名、文件名、签名兼容或 Gadget 参数时删除失效输出。
- 重新生成前删除旧输出；生成失败时删除本次输出目录。
- 导出后保留最新输出，以便继续安装、分享或再次导出；选择新 APK、修改参数、重新生成或下次启动时再清理。
- FileProvider 同时允许新的缓存工作目录和旧文件目录，保证升级兼容。

## 验证

- JVM 文件系统测试覆盖旧会话清理、旧版目录迁移、输出定向删除和选择目录删除。
- 运行管理器单元测试与 release 构建。
- 不在第二台设备上执行安装或测试。

## 不在范围内

- 不改变外层 APK 的组成和 `assets/base.apk` 的字节内容。
- 不删除用户已经导出到公共下载目录的 APK。
- 不实现针对第三方正版、授权或完整性校验的身份伪造。
